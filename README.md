# c2py — транслятор підмножини C на flex/bison

Практична робота з курсу «Теорія програмування».
Котілєвський Григорій, група ТК-31, ФКНК КНУ імені Тараса Шевченка.

Програма читає програму на C, будує абстрактне синтаксичне дерево (AST) за допомогою
LALR(1)-парсера, згенерованого **bison** (сучасний yacc), а лексер — **flex** (сучасний lex).
Далі по дереву можна:

* **виконати** програму — інтерпретатор AST (`--run`);
* **перекласти** її на Python 3 — генерація коду (`--py`);
* **подивитися** дерево у браузері — інтерактивна візуалізація на d3.js (`make demo`).

```
  .c ──► flex (lexer.l) ──► токени ──► bison (parser.y, LALR(1)) ──► AST
                                                                     │
                                       семантичний аналіз (sema.c) ◄─┘
                                       │ типи, області видимості, помилки
                     ┌─────────────────┼──────────────────┐
                     ▼                 ▼                  ▼
              інтерпретатор      генератор Python      JSON → d3.js
               (interp.c)        (codegen_py.c)        (web/)
```

## Що підтримується

Це підмножина C, але достатня для нормальних програм (див. `examples/`):

* типи `int`, `char`, `long`, `short` (усі як ціле), `double`, `float`, `void`;
* глобальні й локальні змінні, одновимірні масиви з ініціалізацією `{...}`;
* функції з параметрами, рекурсія, прототипи, масиви як параметри (`int a[]`);
* `if / else`, `while`, `do-while`, `for` (у т.ч. `for (int i = ...)`), `break`, `continue`, `return`;
* усі звичайні операції з пріоритетами як у C: `= += -= *= /= %=`, `?:`, `|| &&`,
  `== != < > <= >=`, `+ - * / %`, унарні `- + !`, префіксні та постфіксні `++ --`, приведення `(int)x`;
* вбудовані `printf` (з `%d %i %u %x %c %s %f %e %g`, шириною і точністю), `putchar`, `abs`, `fabs`, `sqrt`, `pow`;
* коментарі `//` і `/* */`; рядки `#include`/`#define` просто пропускаються.

Чого немає: вказівників, структур, рядків як змінних, `switch`, препроцесора.

## Збірка і запуск

Потрібні `gcc`, `make`, `flex`, `bison` і `python3` (Linux, macOS або WSL на Windows).

```bash
sudo apt install build-essential flex bison python3   # Ubuntu / WSL
make
```

```bash
./build/c2py --tokens examples/misc.c     # 1. лексичний аналіз
./build/c2py --ast    examples/misc.c     # 2. дерево розбору в терміналі
./build/c2py --run    examples/sort.c     # 3. виконання інтерпретатором
./build/c2py --py     examples/sort.c     # 4. трансляція в Python
./build/c2py --py examples/sort.c -o sort.py && python3 sort.py
make demo                                 # 5. веб-візуалізація: http://localhost:5050
make test                                 # порівняння з gcc на всіх прикладах
make conflicts                            # граматики з конфліктами для пояснення теорії
```

## Веб-візуалізація

`make demo` (або `python3 server.py`) запускає локальний сервер і відкриває браузер.
Зліва — редактор коду, справа вкладки:

* **Дерево** — AST на d3.js: колір вузла означає категорію (оголошення / оператор / операція /
  змінна / літерал), клік згортає піддерево, наведення підсвічує відповідний рядок коду,
  а курсор у редакторі — вузли цього рядка. Є масштабування, експорт у SVG і кнопка
  **«Відтворити згортки»** — вузли з'являються в тому порядку, в якому LR-парсер робить
  reduce (знизу вгору, post-order).
* **Токени** — результат роботи flex.
* **Python** — згенерований код.
* **Вивід** — результат інтерпретатора і згенерованого Python поруч, з перевіркою, що вони однакові.

Бібліотеки (d3, CodeMirror) лежать у `web/vendor/`, тож усе працює без інтернету.

## Тести

`make test` компілює кожен приклад справжнім `gcc`, запускає, а потім порівнює вивід
з інтерпретатором і зі згенерованим Python. Програми з `examples/errors/` мають
завершуватися з помилкою (синтаксичною, семантичною або помилкою виконання).

```
  ok    examples/factorial.c
  ok    examples/misc.c
  ...
passed: 13, failed: 0
```

## Структура

```
src/lexer.l        лексер (flex)
src/parser.y       граматика + побудова AST (bison)
src/ast.c/.h       вузли дерева, друк у текст і JSON
src/sema.c/.h      семантичний аналіз: таблиця символів, типи, перевірки
src/interp.c/.h    інтерпретатор AST
src/codegen_py.c   генератор коду на Python
src/main.c         точка входу, режими роботи
web/               сторінка візуалізації (d3.js + CodeMirror)
server.py          локальний сервер для web/
examples/          приклади програм (і програми з помилками)
tests/             додаткові тести і скрипт порівняння з gcc
docs/THEORY.md     теорія: LALR(1), як працює yacc, конфлікти
docs/conflicts/    маленькі граматики з shift/reduce та reduce/reduce конфліктами
```

## Про граматику

Граматика в `src/parser.y` — 102 правила, автомат LALR(1) має 188 станів
(повний звіт: `build/parser.output` після `make`). Граматика виразів навмисно
неоднозначна (`expr: expr '+' expr | ...`), а неоднозначності розв'язані
оголошеннями `%left / %right / %precedence` — так само, як у класичних прикладах yacc.
Висячий `else` теж розв'язаний явно. Bison не видає жодного попередження.

Детальніше — у [docs/THEORY.md](docs/THEORY.md).
